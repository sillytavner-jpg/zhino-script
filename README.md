## 本次重点

**A5.3.10** —— 大总结链路重构（内部质量版）。

### 问题

「大总结V2（时间线）」+「角色记忆更新」这对组合，项目里原有**三套各写各的实现**，行为不一致：

| 入口 | 并发 | 耗时日志 | AbortSignal |
|---|---|---|---|
| 自动触发大总结 | ✅ | ✅ | ❌ |
| 手动"重新总结" / 卡内触发 | ❌ **串行** | ❌ | ❌ |
| 批量总结 | ❌ **串行** | ❌ | ✅ |

也就是说：在总览页点"重新总结"时，两条链路是串着跑的 ——
表现为**"大总结事件字出完了，才开始分析角色记忆"**，白白多等一倍时间。

### 修复

新增 `core/summaryChain.ts` 公共链路，三条入口统一改调，一次改全生效：

1. **并发执行** —— 两条链路同时发请求（口径对齐自动触发链路）
2. **耗时日志** —— 每任务耗时 + 总耗时，日志直接写判据
   （`≈最长者`=真并发 / `≈各任务之和`=串行），一眼可查
3. **AbortSignal 透传** —— 三条链路都支持外部中止
4. **续跑机制** —— 失败时已成功的部分挂在 `err.partial`，上层只重试失败那条
5. **重试粒度明确** —— 自动重试只补失败项（不白跑已成功的）；手动"重新总结"整链重跑 + 失败回滚旧版

### 兼容性

存储格式 / 设置项 / UI 全不变，无迁移，输出内容一致。
仅调度方式由串行改并发。若渠道并发会限流（429），可在
**设置 → 调度模式** 切「排队模式（1个1个）」。
