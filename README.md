## 本次重点

**A5.3.11** —— 重试机制统一（全项目只保留一处重试）。

### 问题

所有分析模块的唯一 API 入口 `callGenerateRaw` **自带一层重试**（默认 3 次），
而大总结**外层还有一层**重试循环（也是 3 次）。两层叠在一起 → 最多 **3 × 3 = 9 次**。
真出问题时用户要干等 9 轮，点「停止重试」也未必立刻停得下来。

### 修复

拆掉所有内层重试，**唯一重试点 = 后台队列**：

| 改动 | 说明 |
|---|---|
| `callGenerateRaw` 只发一次 | 删掉内层 for 循环与重试弹窗，失败即抛 |
| **新增队列级统一重试** | `backgroundQueue.runTaskWithRetry()`：任务失败 → 弹倒计时窗 → 重跑同一任务，上限 `apiMaxRetries`（默认 3） |
| 大总结去掉链内重试循环 | 只跑一次，失败交给队列 |
| embedding 三处内层循环拆除 | embedding / 批量 / rerank 各只发一次 |
| 废弃弹窗清理 | 旧 `apiRetryStatus` / `summaryRetryStatus` 全部删除，换成统一的 `queueRetryStatus` |

**覆盖面**：所有后台任务自动获得统一重试，模块代码零改动 ——
小总结、大总结、梦呓、动态人设、角色记忆、世界推进、关系分析、人格分析、世界书蒸馏、向量生成。

**特意保留**：批量总结仍走「每批失败 → 暂停 → 用户点继续」的手动续跑（它不走队列，就是人工把关每一批）。

### 兼容性

重试次数仍读 `apiMaxRetries`（默认 3）；内容被过滤 / 输出截断仍直接放弃不浪费轮次。
存储格式 / 设置项 / 其它 UI 全不变，无迁移。
